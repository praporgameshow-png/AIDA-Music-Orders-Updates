# AIDA Music Orders v1.0.4 — Direct MiniChat Integration Design

**Дата:** 31.08.2026  
**Статус:** утверждённый дизайн, готов к пользовательскому ревью перед планом реализации

## 1. Цель

Выпустить AIDA Music Orders v1.0.4, в которой музыкальная награда `AIDA MUSIC` из VK Video Live обрабатывается напрямую через MiniChat без обязательного Streamer.bot.

Целевая цепочка:

`VK Video Live reward → MiniChat → AIDA MiniChat Bridge → AIDA Music Orders API → очередь → OBS`

AIDA должна сама:

- получать событие награды из MiniChat;
- находить ник зрителя и музыкальную ссылку;
- принимать/отклонять заказ через уже существующий локальный API AIDA на `127.0.0.1:18765`;
- отправлять зрителю результат обратно в VK Video Live через MiniChat;
- при отклонении награды возвращать баллы, **если прямой протокол возврата подтверждён реальным тестом**;
- работать без Streamer.bot для музыкальной награды.

## 2. Что сохраняем из v1.0.3

Рабочий движок AIDA Music Orders v1.0.3 не переписывается и не патчится внутри EXE на первом этапе.

Сохраняются без изменения:

- очередь заказов;
- локальный API `POST http://127.0.0.1:18765/api/order`;
- OBS-плеер `http://127.0.0.1:18765/player?client=obs`;
- YouTube / YouTube Music;
- VK Video;
- Яндекс Музыка;
- YouTube LOCAL FALLBACK;
- VK FAST/FALLBACK;
- ограничения очереди;
- повторные заказы;
- один активный заказ на зрителя;
- чёрный список;
- история заказов;
- CUSTOMER-лицензирование и 48-часовой trial;
- OWNER-режим без проверки trial.

v1.0.3 остаётся резервной рабочей версией и не перезаписывается.

## 3. Почему отдельный Bridge

Исходник основного AIDA Music Orders v1.0.3 сейчас не является нормальной рабочей исходной веткой для безопасного изменения; доступна собранная рабочая OWNER-версия. Поэтому прямую MiniChat-интеграцию добавляем отдельным маленьким процессом `AIDA MiniChat Bridge`, который поставляется вместе с AIDA v1.0.4 и запускается автоматически.

Преимущества:

- не ломаем рабочий плеер и fallback-механику;
- Bridge можно тестировать независимо;
- при падении Bridge ручные заказы AIDA и OBS-плеер продолжают работать;
- Bridge легко заменить внутренним модулем позже, когда будет нормальная исходная ветка AIDA.

## 4. MiniChat API

MiniChat предоставляет локальный WebSocket:

`ws://127.0.0.1:4848/Chat`

Bridge использует его для чтения событий и отправки сообщений.

Основные входные типы:

- `Type = "Message"`;
- `Type = "Live"`;
- `Live.Type = "Reward"`;
- сервис VK Video Live может приходить под актуальным именем MiniChat (`VKVideoLive`, `VKPlay` или иным совместимым alias), поэтому сервис сопоставляется по конфигурируемому списку, а не одной жёсткой строке.

Bridge должен уметь извлекать ссылку из:

- обычного текстового поля;
- `MessageKit` элемента типа `URL`;
- вложенных полей награды;
- сырого JSON как последнего fallback.

Поддерживаемые URL:

- `youtube.com`;
- `youtu.be`;
- `music.youtube.com`;
- `vkvideo.ru`;
- `vk.com/video`;
- `vk.ru/video`;
- `music.yandex.ru`;
- `music.yandex.com`.

## 5. Определение музыкальной награды

Bridge реагирует только на награду, название которой после нормализации равно `AIDA MUSIC`.

Нормализация:

- trim;
- case-insensitive;
- схлопывание повторных пробелов;
- допускается конфигурируемое название в `bridge_config.json`.

Любые другие награды Bridge игнорирует.

## 6. Поток успешного заказа

1. MiniChat присылает событие награды.
2. Bridge проверяет, что это `AIDA MUSIC`.
3. Bridge извлекает `event_id/GUID`, ник, user ID, сервис и ссылку.
4. Bridge проверяет дедупликацию события.
5. Bridge отправляет в AIDA:

```json
{
  "nick": "PrapoR_ShoW",
  "message": "https://youtu.be/...",
  "source": "VK Video Live — AIDA MUSIC Direct"
}
```

6. Если AIDA отвечает `ok=true` или `accepted=true`, Bridge отправляет через MiniChat в тот же сервис:

`🎵 @<ник>, заказ принят и добавлен в очередь.`

7. Награда считается успешно обработанной.

## 7. Поток отказа

AIDA остаётся единственным источником бизнес-решения о принятии заказа.

Причины отказа могут включать:

- нет поддерживаемой ссылки;
- заказы закрыты;
- чёрный список;
- повторный заказ;
- лимит очереди;
- один активный заказ на зрителя;
- недоступный/неподдерживаемый ролик;
- иные ответы API.

Bridge отправляет зрителю понятный текст причины через MiniChat.

Если прямой механизм возврата баллов подтверждён, Bridge после отказа вызывает его ровно один раз.

Если возврат баллов не подтверждён, сборка считается **TEST/RC**, а не продаваемой v1.0.4.

## 8. Дедупликация

Одно и то же событие награды не должно создать два заказа.

Ключ дедупликации:

1. `GUID/event_id`, если он есть;
2. иначе hash от `service + user_id + reward_name + url + event_timestamp`.

Хранилище — маленький локальный JSON/SQLite cache с TTL 10 минут.

Повторное событие в TTL игнорируется без повторного сообщения и без повторного возврата баллов.

## 9. Соединение и нагрузка

Bridge должен быть лёгким:

- одно WebSocket-соединение;
- никаких циклов OCR/скриншотов;
- reconnect с backoff 1 → 2 → 5 секунд, максимум 5 секунд;
- локальный HTTP к AIDA только при награде;
- логирование только событий AIDA MUSIC и ошибок;
- CPU в idle практически нулевой.

## 10. Запуск и жизненный цикл

В v1.0.4 поставляются:

- `AIDA Music Orders.exe` — проверенная v1.0.3 основа;
- `AIDA MiniChat Bridge.exe`;
- `bridge_config.json`;
- новый `START_AIDA_OWNER.cmd` / CUSTOMER launcher;
- README/инструкция.

Launcher:

1. не должен печатать красные PowerShell-ошибки;
2. запускает AIDA;
3. ждёт готовности `127.0.0.1:18765`;
4. запускает Bridge;
5. не создаёт второй экземпляр Bridge;
6. при закрытии AIDA Bridge может завершиться автоматически либо оставаться с безопасным reconnect — окончательное поведение выбирается в реализации по простоте и надёжности.

## 11. Настройки Bridge

`bridge_config.json`:

```json
{
  "enabled": true,
  "minichat_ws": "ws://127.0.0.1:4848/Chat",
  "aida_order_api": "http://127.0.0.1:18765/api/order",
  "reward_name": "AIDA MUSIC",
  "reply_on_accept": true,
  "reply_on_reject": true,
  "refund_on_reject": true,
  "dedupe_ttl_seconds": 600
}
```

CUSTOMER и OWNER используют один формат конфига.

## 12. Обратная совместимость

- Старый Streamer.bot action `AIDA MUSIC — Заказ из VK` не удаляется автоматически с компьютера пользователя.
- Инструкция v1.0.4 требует **отключить его trigger**, чтобы не было дублей.
- Bridge должен обнаруживать вероятный дубль и игнорировать его по dedupe.
- Ручное добавление ссылки в AIDA продолжает работать.
- OBS Browser Source URL не меняется.

## 13. Возврат баллов — обязательный release gate

Публичный MiniChat API документирует WebSocket события и отправку сообщений, но не документирует отдельную команду `refund reward`/`reject reward`.

Поэтому до релиза выполняется протокольный spike на реальной награде VK Video Live:

1. записать полный входящий JSON `AIDA MUSIC`;
2. определить идентификаторы награды/активации;
3. проверить, есть ли прямой MiniChat запрос/REST/WebSocket-команда для отказа;
4. если есть — реализовать и проверить фактический возврат баллов;
5. если нет — проверить, можно ли корректно вызвать возврат через доступный локальный MiniChat API без Streamer.bot;
6. если прямого способа нет, **не публиковать обещание «Streamer.bot не нужен для возврата баллов»**.

Для финальной продаваемой v1.0.4 выбран критерий: автоматический возврат баллов должен быть подтверждён тестом на реальной VK-награде.

## 14. Тестирование

### Автоматические тесты Bridge

- парсинг Reward JSON;
- MessageKit URL;
- YouTube short URL;
- VK Video URL;
- Яндекс Музыка URL;
- отсутствующая ссылка;
- неправильное название награды;
- дедупликация GUID;
- повторное событие без GUID;
- accepted API response;
- rejected API response;
- AIDA offline;
- MiniChat reconnect;
- отправка chat reply payload.

### Реальная приёмка на стрим-ПК

1. MiniChat запущен, Streamer.bot полностью закрыт.
2. AIDA v1.0.4 запущена новым launcher.
3. OBS видит плеер по прежнему URL.
4. Активировать `AIDA MUSIC` с YouTube ссылкой.
5. Заказ появляется в AIDA ровно один раз.
6. В чат приходит «заказ принят».
7. Активировать награду с плохой/пустой ссылкой.
8. В чат приходит отказ.
9. Баллы реально возвращаются.
10. Проверить YouTube LOCAL FALLBACK.
11. Проверить VK Video.
12. Проверить Яндекс Музыку.
13. Закрыть/открыть MiniChat — Bridge переподключается.
14. Перезапустить AIDA — настройки/история не ломаются.

## 15. Версии сборок

После приёмки формируются:

- `AIDA_Music_Orders_v1.0.4_OWNER.zip`;
- `AIDA_Music_Orders_v1.0.4_CUSTOMER.zip`;

## 17. GitHub / Update

Перед публикацией:

- сохранить v1.0.3 release как резерв;
- создать release v1.0.4;
- загрузить CUSTOMER/UPDATE assets;
- вычислить SHA-256 по фактическим файлам;
- обновить manifest только после загрузки assets;
- проверить download URL и hash на чистой копии.

## 18. Критерии готовности

v1.0.4 считается готовой к продаже только если одновременно выполнено:

- Streamer.bot закрыт;
- реальная VK Video Live награда принимается напрямую через MiniChat;
- ник и URL извлекаются корректно;
- заказ создаётся ровно один раз;
- AIDA принимает/отклоняет заказ своим существующим API;
- ответ в VK-чат отправляется напрямую через MiniChat;
- при отказе баллы реально возвращаются;
- OBS-плеер и существующие fallback-механизмы работают как в v1.0.3;
- OWNER не показывает trial;
- CUSTOMER сохраняет 48-часовой trial;
- все автоматические тесты PASS;
- реальная приёмка PASS;
- только после этого магазин и update manifest переключаются на v1.0.4.

## 19. Не входит в v1.0.4

- переписывание основного AIDA Music Orders EXE;
- замена MiniChat собственным чатом;
- интеграция других наград AIDA;
- изменение OBS Browser Source URL;
- изменение цены;
- новая система лицензирования;
- облачный relay для чата;
- поддержка платформ вне уже доступных через MiniChat музыкальных заказов.
